# B1 · บันทึกการแก้บั๊ก (กรอกให้ครบทั้ง 6 จุด)

> แต่ละบั๊กให้เขียน 4 อย่าง: ไฟล์ · บรรทัด · สาเหตุ (ทำไมทำงานผิด) · แก้อย่างไร
> เขียนด้วยคำของตัวเอง — จุดนี้จะถูกถามใน oral

## บั๊กที่ 1 — อาการ: Console เตือนสีเหลืองเรื่องรายการ
- ไฟล์/บรรทัด: RequestList บรรทัด 9
- สาเหตุ: มาจาก RequestList ไม่ได้กำหนด key จาก request.id ทำให้ key มันซ้ำซ้อนกัน
- แก้อย่างไร: ใส่ key={request.id} เพื่อทำให้ key ไม่ซ้ำซ้อนกัน

## บั๊กที่ 2 — อาการ: ตัวเลข "รอดำเนินการ" ในแผงสรุปไม่ตรงกับที่เห็น
- ไฟล์/บรรทัด: DashboardPage บรรทัด 47
- สาเหตุ: มาจากการกำหนด summary ของ pending โดยที่กำหนดการกรองของ pending: requests.filter((request) => request.status === 'completed').length, เป็น completed มันเลยไปนำของ completed มาใส่เข้าใน pending
- แก้อย่างไร: เปลี่ยนการกำหนด status จาก completed เป็น pending

## บั๊กที่ 3 — อาการ: กดตัวกรอง "รอดำเนินการ" แล้วได้รายการที่ไม่ใช่
- ไฟล์/บรรทัด: DashboardPage บรรทัด 55
- สาเหตุ: มาจากการใช้ logic เปรียบเทียบ request.status ที่ไม่ถูกต้องโดยที่กำหนดเป็น !== อธิบายได้ว่าจะนำเอา statusFilter ที่กรองทั้งหมดมาแบบ กรองไม่ถูกต้อง
- แก้อย่างไร: แก้ไข logic การเปรียบเทียบโดยเปลี่ยนจาก !== เป็น === จะได้คัดกรองอย่างถูกต้อง

## บั๊กที่ 4 — อาการ: เปลี่ยน URL จาก REQ-001 เป็น REQ-002 แล้วข้อมูลไม่เปลี่ยน
- ไฟล์/บรรทัด: RequestDetailPage บรรทัด 28
- สาเหตุ: บริเวณ useEffect เรื่องการดึงข้อมูลใหม่เมื่อ requestId ใน URL เปลี่ยนแปลง แต่ลืมใส่ requestId ลงไปใน Dependency Array ทำให้คอมโพเนนต์ไม่รู้ว่า URL เปลี่ยน
- แก้อย่างไร: เพิ่ม requestId เข้าไปบริเวณบรรทัดที่ 28 แบบนี้ [reloadKey, requestId] เพื่อ เมื่อเปลี่ยนแปลง URL จะเรียกการดึงข้อมูลมาใหม่

## บั๊กที่ 5 — อาการ: กด "ลบ" แล้วรายการยังอยู่ ต้องรีเฟรชถึงหาย
- ไฟล์/บรรทัด: DashboardPage บรรทัด 53
- สาเหตุ: จาก handleDelete เมื่อกดลบแล้วจะเอา state requests เดิมที่ยังไม่ได้ลบรายการออกไปอัปเดตซ้ำ
- แก้อย่างไร: แก้ไข state ของ setRequests จากการเอา requests เดิมมาอัปเดตแก้ไขเป็น nextRequests ให้อัปเดตข้อมูลใหม่

## บั๊กที่ 6 — อาการ: กด "Reset Demo Data" แล้วหน้าพัง/ว่างเปล่า
- ไฟล์/บรรทัด: DashboardPage บรรทัด 75
- สาเหตุ: จากการที่ฟังก์ชัน resetRequests เป็นแบบ Asynchronous คืนค่าเป็น Promise แต่ในฟังก์ชัน handleReset มีการเรียกใช้และนำค่าไปใส่ setRequests ทันที โดยไม่มีการรอ ทำให้ state ได้รับค่าเป็น Promise แทนที่จะเป็น Array ของข้อมูล
- แก้อย่างไร: เติมคำสั่ง await ไว้หน้าการเรียกฟังก์ชันเพื่อให้รอการรอรับข้อมูลก่อนในไปเซ็ตค่า
