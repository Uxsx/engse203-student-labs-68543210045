## วิธีกรอก (อ่านก่อนเริ่ม)

กรอกให้ครบ **ทั้ง 6 บั๊ก** · แต่ละบั๊กเขียน 3 อย่างด้วย **คำของตัวเอง** (จะถูกสุ่มถามใน oral)

| คอลัมน์ | ใส่อะไร | ตัวอย่างสิ่งที่เขียน *(บั๊กสมมติ)* |
|---|---|---|
| **ไฟล์ : บรรทัด** | ไฟล์ที่แก้ + เลขบรรทัด | `Foo.jsx : 12` |
| **สาเหตุ** | **ทำไม** มันทำงานผิด (ไม่ใช่แค่ "พิมพ์ผิด") | "ใส่วงเล็บท้ายชื่อฟังก์ชัน เลยถูกเรียกทันทีตอน render" |
| **แก้อย่างไร** | เปลี่ยน**จากอะไร**เป็น**อะไร** | "เอาวงเล็บออก จาก `onClick={fn()}` เป็น `onClick={fn}`" |

> เคล็ด: เลขบรรทัดดูได้จากแถบซ้ายใน VS Code หรือจากข้อความ error ใน Console (เช่น `RequestList.jsx:9`)

## บันทึกของฉัน — กรอกทั้ง 6 บั๊ก

| # | อาการ (ให้มาแล้ว) | ไฟล์ : บรรทัด | สาเหตุ (ทำไมผิด) | แก้อย่างไร |
|---|---|---|---|---|
| 1 | Console เตือนสีเหลืองเรื่องรายการ (list) | `RequestList.jsx : 9`  | มาจาก RequestList ไม่ได้กำหนด key จาก request.id ทำให้ key มันซ้ำซ้อนกัน | ใส่ key={request.id} เพื่อทำให้ key ไม่ซ้ำซ้อนกัน |
| 2 | ตัวเลข "รอดำเนินการ" ในแผงสรุปไม่ตรงกับที่เห็นจริง | `DashboardPage.jsx : 47` | มาจากการกำหนด summary ของ pending โดยที่กำหนดการกรองของ pending: requests.filter((request) => request.status === 'pending').length เป็น completed มันเลยไปนำของ completed มาใส่เข้าใน pending  | เปลี่ยนการกำหนด status จาก completed เป็น pending |
| 3 | กดตัวกรอง "รอดำเนินการ" แล้วได้รายการที่ไม่ใช่ | `DashboardPage.jsx : 54` | มาจากการใช้ logic เปรียบเทียบ request.status ที่ไม่ถูกต้องโดยที่กำหนดเป็น !== อธิบายได้ว่าจะนำเอา statusFilter ที่กรองทั้งหมดมาแบบ กรองไม่ถูกต้อง | แก้ไข logic การเปรียบเทียบโดยเปลี่ยนจาก !== เป็น === จะได้คัดกรองอย่างถูกต้อง |
| 4 | เปลี่ยน URL `REQ-001` → `REQ-002` แล้วข้อมูลไม่เปลี่ยน | `RequestDetailPage.jsx : 28` | บริเวณ useEffect เรื่องการดึงข้อมูลใหม่เมื่อ requestId ใน URL เปลี่ยนแปลง แต่ลืมใส่ requestId ลงไปใน Dependency Array ทำให้คอมโพเนนต์ไม่รู้ว่า URL เปลี่ยน | เพิ่ม requestId เข้าไปบริเวณบรรทัดที่ 28 แบบนี้ [reloadKey, requestId] เพื่อ เมื่อเปลี่ยนแปลง URL จะเรียกการดึงข้อมูลมาใหม่ |
| 5 | กด "ลบ" แล้วรายการยังอยู่ ต้องรีเฟรชถึงหาย | `DashboardPage.jsx : 73` | จาก handleDelete เมื่อกดลบแล้วจะเอา state requests เดิมที่ยังไม่ได้ลบรายการออกไปอัปเดตซ้ำ | แก้ไข state ของ setRequests จากการเอา requests เดิมมาอัปเดตแก้ไขเป็น nextRequests ให้อัปเดตข้อมูลใหม่ |
| 6 | กด "Reset Demo Data" แล้วหน้าพัง/ว่างเปล่า | `DashboardPage.jsx : 93` | จากการที่ฟังก์ชัน resetRequests เป็นแบบ Asynchronous คืนค่าเป็น Promise แต่ในฟังก์ชัน handleReset มีการเรียกใช้และนำค่าไปใส่ setRequests ทันที โดยไม่มีการรอ ทำให้ state ได้รับค่าเป็น Promise แทนที่จะเป็น Array ของข้อมูล | เติมคำสั่ง await ไว้หน้าการเรียกฟังก์ชันเพื่อให้รอรับข้อมูลก่อนไปเซ็ตค่า |
