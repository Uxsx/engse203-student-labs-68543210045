# Database Choices — Week 11

> ตัวอย่างคำตอบสำหรับใช้ทบทวนและปรับเป็นคำอธิบายของตนเองก่อนส่ง

## 1. ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB

ข้อมูลคำร้องและผู้ใช้มีโครงสร้างค่อนข้างชัด เช่น คำร้องมีผู้แจ้ง สถานะ
และประเภทคำร้อง จึงเหมาะกับตารางและความสัมพันธ์แบบ relational database.
SQLite มี foreign key และ JOIN ช่วยรักษาความสัมพันธ์และดึงชื่อผู้แจ้งพร้อมคำร้องได้
โดยไม่ต้องดูแล database server แยก เหมาะกับขนาดและวิธีรันของโปรเจกต์นี้
ส่วน MongoDB เหมาะกว่าเมื่อข้อมูลมีรูปแบบยืดหยุ่นหรือเปลี่ยน schema บ่อย

## 2. ถ้าเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง

การเปลี่ยนจาก SQLite ไป MongoDB กระทบชั้น service แน่นอน เพราะวิธีเชื่อมต่อ
การ query และรูปแบบข้อมูลเปลี่ยนไป หากใช้ MongoDB driver แบบ asynchronous
service จะต้องคืน Promise ด้วย controller จึงต้องรอผลลัพธ์และส่ง error
ไปยัง middleware ให้ถูกต้อง ส่วน frontend ควรเปลี่ยนน้อยที่สุดหาก API ยังคง
สัญญา request/response เดิม

## 3. async จำเป็นเมื่อไร และไม่จำเป็นเมื่อไร

การทำงานกับบริการที่ต้องรอ I/O เช่น database server ที่อยู่คนละเครื่อง
หรือ API ภายนอก ควรใช้ async เพื่อไม่บล็อกการทำงานระหว่างรอผลลัพธ์
SQLite แบบ synchronous ในตัวอย่างนี้เหมาะกับการสอนและงานขนาดเล็กที่รันในเครื่อง
เพราะใช้ง่ายและไม่ต้องจัดการ Promise ทุกจุด อย่างไรก็ตาม งาน production ที่มี
คำขอพร้อมกันมากควรพิจารณา driver แบบ async หรือ database server
